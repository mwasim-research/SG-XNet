# SG-XNet: Structured Graph eXtended Network — version 2

Code, result files and analysis scripts for the revised (round-3) version of

> R. Khan, M. Wasim, S. Alahmari, A. Waseem. *Structured Graph eXtended Network (SG-XNet): A Model for Transfer
> Learning in Graph Neural Networks (GNNs) for Node Classification.* Submitted to PeerJ Computer Science
> (manuscript CS-2024:10:108662).

SG-XNet is a GNN whose first message-passing layer is a GraphSAGE layer (a node's own representation and an
aggregate of its neighbours' representations, with separate weights), followed by GCN layers. Version 2 of this
repository is a controlled re-evaluation of SG-XNet against GCN, GraphSAGE, GAT, GIN and an MLP for transfer learning
in node classification. **Version 1 (the original scripts) is kept unchanged in [`legacy_v1/`](legacy_v1/); its results
are superseded and should not be used** (see "Changes from version 1" below).

## What the revised paper finds (short version)

- Direct weight transfer helps substantially only when source and target share features and labels (the
  ACMv9 / Citationv1 / DBLPv7 benchmark); it does not help on CiteSeer→Cora, DBLP→PubMed or heterophilic targets.
- On the aligned graphs and under standard per-dataset tuning, SG-XNet loses less of its zero-shot accuracy when
  fine-tuned with 1–5 labels per class than GCN, GraphSAGE and GIN, but not than GAT or the MLP.
- This robustness comes mainly from the selected configuration, not from the layer order; freezing, L2-SP
  fine-tuning and tuning for transfer give other GNNs similar robustness, and frozen GCN and GCN with UDAGCN are the
  most accurate of the approaches tested.

The paper does **not** claim that the GraphSAGE-then-GCN design improves transfer in general.

## Installation

Python 3.11 with the versions in `requirements.txt` (torch 2.8.0, torch_geometric 2.6.1, numpy, scipy, pandas,
matplotlib). The experiments were run on a MacBook Pro (Apple M4 Pro, CPU only, 10 worker processes); some post hoc
analyses were run on Linux (x86) with the same code, and cross-platform differences were below 0.2 points on the
checked runs.

```bash
python3.11 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

`run.sh` uses `./.venv` if it exists and otherwise creates it from `requirements.txt`.

## Reproducing the paper

**From the released result files (minutes, no training):**

```bash
bash scripts/unpack_results.sh          # unzips results_archive/*.zip into results/ and results_posthoc_*/
python paper/ms_tables.py               # main-text tables (writes paper/output/numbers.json)
python paper/ms_supp.py                 # supplementary tables (paper/output/supp_tables.tex)
python paper/ms_figs.py                 # Figures 4, 5, 7, 8 (results_posthoc_overnight/figures/)
python paper/heat3.py                   # Figure 3 (results_posthoc_review3/figures/)
python paper/rv3.py; python paper/rv3b.py   # robustness analyses added in the final revision
```

`paper/README.md` lists which script produces which number. `bash run.sh analyze-full` and `bash run.sh figures-full`
rebuild the pipeline's own summaries (`results/analysis/SUMMARY_full.md`) and figures from the per-run files.

**From scratch (days of CPU time):** `bash run.sh all` runs tuning, pretraining, the main study and the baselines;
`bash run.sh explore` the exploratory SG-XNet-G; the post hoc analyses are run with the scripts in `posthoc/*/`.
Every stage is resumable. `bash run.sh smoke` is a 1–2 minute end-to-end test.

## Protocol (summary; the paper gives the full description)

| Item | Choice |
|---|---|
| Transfer pairs | CiteSeer→Cora, DBLP→PubMed; the six directed ACDNE pairs; squirrel→chameleon, amazon-ratings→roman-empire, CiteSeer→chameleon; post hoc: the six Twitch pairs |
| Model layout | dataset-specific linear `encoder` → transferable `body` (first K−1 message-passing layers) → `out` (K-th layer, outputs the classes). Pairs with shared features and labels transfer all three parts; other pairs transfer the body only |
| Conditions | from scratch; fine-tuned (all parameters trained); frozen (body fixed, and on aligned pairs also the copied encoder; output layer trained); zero-shot (aligned pairs; no target training); negative controls (shuffled source labels; random source graph) |
| Target splits | k ∈ {1, 3, 5, 10, 20} labelled nodes per class, 30 validation nodes per class, all other nodes test; 10 splits; split i also fixes the initialisation seed and selects the source model pretrained with seed i |
| Tuning | per model and dataset: 30 random configurations × 3 tuning splits (k = 20, seeds 1000–1002, drawn independently of the evaluation splits; up to 500 epochs, patience 50) over depth, width, dropout, learning rate, weight decay, residual connections, LayerNorm, GAT heads and the GraphSAGE/SG-XNet aggregator. The public-split results (Table 3) use a separate tuning on the public splits (`results/selected_public.json`) |
| Training | Adam, full batch, up to 1000 epochs, early stopping on validation (patience 100); the learning rate of every final run, including pretraining, is chosen from {1e-2, 5e-3, 1e-3} on validation; validation is first evaluated after the first update |
| Metrics | accuracy (single-label graphs); micro- and macro-F1 on the multi-label ACDNE graphs, predicting for each test node its r highest-scoring labels, where r is the node's true number of labels |
| Statistics | paired by split; two-sided paired t-tests with Holm correction within stated families; Wilcoxon p-values in the CSV files; Friedman/Nemenyi used descriptively |
| Failed pretraining | GAT and SG-XNet on CiteSeer→chameleon-filtered (below half of the best model's source score) and GAT on ACMv9→DBLPv7 (a judgement: 64 against 88–89 for every other GNN) are excluded from the main statistics; the paper reports a sensitivity analysis that includes them |

## Result files

`results_archive/` holds eight zip files (about 45 MB in total; model checkpoints, logs and local machine paths removed;
each archive is below 12 MB):

| Archive | Unpacks to | Contents |
|---|---|---|
| `results_main_tune.zip` | `results/tune/` | every tuning run (30 configurations × 3 tuning splits per model and dataset) |
| `results_main_target_acdne.zip` | `results/target/{acmv9,citationv1,dblpv7}/` | target runs on the aligned graphs (all conditions, budgets and splits, including the ablation and the exploratory SG-XNet-G) |
| `results_main_target_other.zip` | `results/target/{cora,pubmed,chameleon_filtered,roman_empire}/` | target runs on the other graphs |
| `results_main_other.zip` | `results/` | pretraining, public-split and self-supervised pretraining runs; `selected_budget20.json`, `selected_public.json` (selected configurations); `datasets.json`; `analysis/` (CSV of every run and every paired test; Markdown summaries); `figures/` |
| `results_posthoc_overnight.zip` | `results_posthoc_overnight/` | L2-SP, CKA, transfer-aware tuning, SG-XNet in UDAGCN |
| `results_posthoc_twitch.zip` | `results_posthoc_twitch/` | Twitch benchmark (tuning, pretraining, target runs) |
| `results_posthoc_night2.zip` | `results_posthoc_night2/` | source-only check (E1) and CKA under L2-SP (E2), with CSV summaries in `analysis/` |
| `results_posthoc_review3.zip` | `results_posthoc_review3/` | plain fine-tuning CKA per run (CSV) and the regenerated Figure 3 |

Each run file records the configuration, the learning rate chosen on validation, the selected epoch, and validation
and test scores. Model checkpoints are not included (5–6 GB); they are regenerated by the pipeline.

## Changes from version 1

Version 1 (in `legacy_v1/`) trained each model once on one split with fixed hyperparameters, computed metrics on all
nodes averaged over 200 epochs, had no validation-based model selection, used different learning rates for SG-XNet
and the baselines, and its "feature extraction" runs did not freeze any layer. Its results are withdrawn. Version 2
replaces it with the protocol above.
